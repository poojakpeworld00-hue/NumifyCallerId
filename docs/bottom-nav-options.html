Trade-offs

Way 1

Segmented inside

Smallest build. Keep both existing fragments and swap them behind a segmented control — no ViewPager2, no adapter merge.

  • Reuses CallHistoryFragment and PhonebookFragment untouched
  • Segment state is trivial to persist across tab switches
  • Every nav label stays visible — best for first-time users

Cost: the segmented control eats ~44dp on every visit, and it's a second row of navigation directly above the first. Two nav layers stacked.

Way 2

Swipe sub-tabs

Standard TabLayout + ViewPager2. Counts in the tab labels give the screen useful information density.

  • Swipe between Recent and Contacts is the gesture users already expect here
  • Active-only labels in the nav free horizontal room, so 5 destinations would still fit later
  • Date group headers (Today / Yesterday) become sticky

Cost: horizontal swipe inside a tab conflicts with swipe-to-delete on list rows. You'd have to pick one.

Way 3

Center action

Says Search is the app's primary job, not a peer of Tools. One merged list — Recent, then Frequently contacted, then A–Z with a fast-scroll rail.

  • No sub-navigation at all inside tab 1
  • Alphabet rail makes 248 contacts reachable in one gesture
  • Frees the whole content area for the list

Cost: the biggest data change — needs a single merged adapter with multiple view types. And a raised FAB overlaps the AdMob banner region; the banner has to sit below the nav, not behind it.

Way 4

Filter chips

Chips replace both sub-tabs and separate destinations. One list, one adapter, filtered — and the set is extensible without touching navigation.

  • Adding "Missed" or "Favourites" later costs one chip, not one screen
  • Floating pill bar reads as more modern and lifts the nav off the banner
  • Chip state maps cleanly onto a single query parameter

Cost: icons-only nav is worse for discoverability — some users never learn what the fourth icon is. And a detached bar plus a banner beneath it makes the bottom feel crowded.

Way 5

Tools as sheet

Tools is a grab-bag, not a place you dwell — a sheet fits its actual use better than a full destination, and it can hold 8+ entries without a scrolling screen.

  • Only 3 real fragments to build and keep in memory
  • Sheet dismisses back to wherever you were — no tab-history bookkeeping in HomeShellActivity
  • Collapsible Recent/Contacts sections mean no sub-nav and no merged adapter

Cost: the fourth nav item behaves differently from the other three, which is a small inconsistency. Your existing back-stack logic (onBackPressed retraces visited tabs) needs a special case for it.

One thing to decide either way: dropping the Home tab removes the only screen that currently hosts the native ad and the Protection card. Ways 1–4 have no obvious home for either. Way 5's Tools sheet can carry Protection, but the native ad slot would need to move into the Calls list as an inline item — worth settling before I build, since it affects DashboardFragment's fate.
